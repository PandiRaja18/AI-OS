# Demo script — 10 minutes

Run everything with `--offline`: the model calls are replayed, so the trace is
identical every time and nothing depends on the network mid-presentation. Say
that out loud once — it reads as engineering discipline, not a shortcut.

Widen the terminal first (120+ columns) so the tables do not wrap.

## 0. Setup (before you present)

```bash
python -m pip install -e .
aios seed
python -m pytest -q          # 57 passed
```

## 1. The claim, in one sentence (30s)

> A goal comes in as a sentence. The platform plans it into a task graph, runs
> the tasks on specialised agents in parallel, reconciles what they disagree on,
> survives tools being down, and stops for a human before anything becomes
> durable knowledge.

## 2. The run (4 min)

```bash
aios run "Prepare the FY26-Q3 quarterly audit review" --offline
```

Narrate against the live trace, in this order:

| Trace line | What to say |
|---|---|
| `memory_recall` | Durable memory from a prior run is recalled and given to the planner. Planning is not stateless. |
| `plan` | Six tasks, each with an owner, dependencies and success criteria. The DAG is validated before anything is dispatched — cycles, unknown deps and unknown agents are rejected and the planner is re-prompted. |
| `dispatch: t3, t4, t5` | One dispatch wave, three tasks, three agents. That is LangGraph `Send` fan-out, not a for-loop. |
| `tool_error … 503` then `task_retry` | The ledger service is down. The *agent* does not decide what to do about it — it reports, and the coordinator applies the retry policy with backoff. |
| `conflict_detected` | The warehouse says 55,700 USD. The prior-quarter memo says 82,600 USD. Nothing silently picks a winner. |
| `re-querying t3_vendor_precedent` | We re-query the **least confident** claimant, with the contradiction as context. |
| `conflict_resolved` | The memo figure was FY-to-date, not single-quarter. Resolved, with the reason recorded in the run. |
| `task_degraded` | The benchmark provider never came back. It is non-critical, so the run continues degraded rather than failing — and the gap gets named in the report. |
| `signoff_requested` | The graph stops. Not a prompt loop waiting — a checkpoint. |

## 3. The gate (1 min)

Point at the panel: the draft summary, the resolved conflict, the degraded task.
Then approve.

```
Approve this run? [Y/n]
```

Then the finish: `memory_promote` promotes four findings with provenance back to
this run, and the task graph and conflict tables print.

Open the report:

```bash
cat .aios/reports/<run_id>.md
```

The "Control gaps and open items" section is the point. It names the resolved
contradiction, the degraded task, and what still needs human judgement.

## 4. Resumability (1 min)

```bash
aios runs
aios trace <run_id> | head -40
aios memory
```

> The run is a checkpoint, not a process. `aios resume <run_id> --approve` works
> tomorrow, from a different shell. The trace is the audit trail.

## 5. The failure you cannot retry your way out of (2 min)

```bash
aios run "Prepare the FY26-Q3 quarterly audit review" \
  --offline --scenario audit_outage --outage ledger_lookup
```

| Trace line | What to say |
|---|---|
| `task_blocked` | Retries exhausted on a *critical* task. Retrying again is pointless. |
| `replan: revision 2` | The planner is re-invoked with the failure context and routes around the dead tool with a documentation cross-check. |
| task table | The blocked task is `superseded`, not deleted — the graph keeps the whole history. |
| no `memory_promote` | The revised report has lower confidence and lands below the promotion bar. The human approved the report; the *platform* still declined to promote it. Two independent gates. |

## 6. Close (1 min)

> Three things I would show a reviewer: the coordinator is pure policy and unit
> tested on its own; every tool call is authorized per principal at the gateway,
> so an agent cannot reach a tool it was not granted; and nothing enters durable
> memory without both a human approval and a confidence threshold.

## If asked

**Where is the LLM?** Two structured calls per task — pick tools, then interpret
evidence — plus the planner. Everything crossing a component boundary is a typed
object, so the coordinator can validate it programmatically.

**Is the data real?** Synthetic, generated by `aios seed`. The numbers were chosen
so one demo exercises a threshold breach, a cross-source contradiction, a flaky
tool and a dead tool.

**What is not built yet?** Vector/graph retrieval behind `SemanticMemory.recall`,
a sandboxed code agent, multi-tenancy, a web UI. The recall interface is the seam
for the first one.

**What would break at scale?** One run at a time per process, and a synchronous
graph. The state, checkpointing and A2A envelope are already the right shape for
a queue between the coordinator and the agents.
